# 1.5 嵌入显示与巡航响应优化

本次定制版本 1.5.9.5 / 26000014，正式发布状态以 GitHub Release 为准。用户授权指定停车 P 档车机检测、覆盖测试和卡片尺寸条操作，只修改高德。

## 入口与尺寸同步

原巡航入口先在 GFrame 线程读取页面，回到 Android 主线程，再发第二个 GFrame 任务读取主题和位置。现改为同一快照读取页面、主题及坐标，一次回传，并在显示入口前应用位置。

尺寸监听从固定大小的按钮改到实际内容容器。地图嵌入区域改变时唤醒地图，重新核对页面与坐标，detach 配对移除监听。不新增尺寸轮询，不修改地图投影、触摸坐标或渲染分辨率。

本机昼夜通知会重复到达。主题通知只在下一动画帧请求快照，不为每次通知另排 160ms 复查；页面、按键、触摸和尺寸变化仍保留结束复查。重复的白天/夜间状态 37、38 不再重置静止保持计时；实际主题变化、页面变化、手势和尺寸变化仍唤醒地图，其他状态的原有唤醒行为保留。静止阈值、定位新鲜度和原生帧率档位保持原样。

原生设置缩放时，“扩展”入口的新布局参数已写入，但其根 ConstraintLayout 保留了旧的约束计算结果，导致入口落后一个尺寸状态。原实现通知的是分类栏容器，入口实际属于设置根容器。现调用实际父容器的 onChildrenLayoutChanged，使子控件约束重新求解，再沿用原有同步布局。没有增加轮询、几何缓存或额外位置检查。

## 已登录时的同步统计查询

固定基础 libautonavi.so 中，GFragmentCruise::onPause 位于 0xa7f528。其内联 CheckAndShowFootprintMilestone 没有可用里程缓存时，先经 Middleware::RequestTaskSync 获取行程统计，到 0xa7ffd8 才调用 hsl::UserUtil::IsLogin。已登录时 0xa7ffdc 转到原清理位置 0xa80374，跳过后面的足迹提示。

本版把这个已有前提放在同步查询之前。已登录时走原跳过分支与清理，未登录时恢复原 GetContext 并继续原路径。有效里程缓存的原路径保留。没有缩短同步等待、改锁、删导航或省略 pause/destroy。

完整基础库 SHA-256：

64974f89eb861f4103ee9e0b7047e978b52c4ede5f77c0072881e3c2eb6ed2df

cruise_milestone.S/.ld 只编译以下四段，共 28 字节。固定基础库可执行段文件偏移与虚拟地址相同。

| 地址 | 长度 | 用途 |
|---|---:|---|
| 0xa7fb7c | 4 | 同步查询前转到登录判断 |
| 0xa7fda4 | 4 | 正常返回跳过 FT 结束诊断日志块 |
| 0xa7fda8 | 16 | 复用该日志块，放置登录判断及原 GetContext 恢复 |
| 0xa80b84 | 4 | 原同步返回路径跳过该日志块 |

登录为真转到原 0xa7ffdc；为假调用原 0xd9ca10，回到 0xa7fb80。原 0xa7ffd8..0xa7ffe0 保持。两条进入复用日志块的旧路径均转向原日志结束位置。构建器校验完整基础库哈希和四段大小，不能把地址套到其他版本。

## 启动与验证

HighRefresh 只在存在更高刷新率模式时更新窗口。更新模块没有缓存下载状态时不再每次启动写空的清理配置。显示比例、清晰度、定位、导航、红绿灯数据、音量和基础帧率策略保持。

日志还确认了自启动权限入口的 ActivityNotFoundException：对已指定组件的 Intent 调用 resolveActivity 不能判定该组件在本机是否存在。改为 PackageManager.resolveActivity(intent, 0) 做原有入口的那一次检查，缺少厂商页面时沿用既有的应用详情页兜底；没有添加多层检查、try/catch 或更改系统权限。

区分 Android 窗口显示、地图内容就绪及宿主完成嵌入。普通控件 gfxinfo 不代替原生地图呈现帧。巡航按钮记录输入入口、GFrame 执行、finish 返回及主线程回调，并确认真实页面、目标进程和入口可见；尺寸测试核对 Activity、Surface 生命周期、两层尺寸、入口及实际点击。

本地证据、截图及 QA 包放在公开仓库之外。临时 PerfProbe 只供检测，release.py 拒绝其 Java 类或 native 标记；最终包重新构建并确认不含采样入口。停车短测不代表实路或长期稳定性。
