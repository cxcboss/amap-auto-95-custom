# 1.2.9.5 播报与交互调整

本版为 1.2.9.5 / 26000011。本轮只交付文件，进行本地编译、签名、对齐和 APK 静态核对，不安装、不运行设备或模拟器测试，不发布 GitHub Release。

## 播报频繁的原因

当前共存基包包含独立的定制播报。`GuideRoad`、`CruiseRoad` 在道路名称变化时调用 `floatapp.tts.ttsService.e()`，通过 80082 协议提交播报文本；导航红绿灯、巡航红绿灯和天气也有各自的调用。它们不读取高德原生极简、智能播报档位，因而会在原生播报之外增加语音。

原来的“导航简洁播报 / 巡航简洁播报”只跳过名称以“桥”或“隧道”结尾的道路，不能限制其他额外播报。额外道路播报的代码默认最短间隔只有 2000 毫秒。此结论来自本地 1.1 APK 的实际类与调用链；没有把每位用户的现有配置都假定为默认值。

## 扩展设置入口与配置

路径：高德设置 → 扩展设置 → 语音。新增“额外语音播报”分组及“仅保留高德播报”操作。红绿灯、天气分类中保留同一开关，修改任何一处都操作同一配置字段。每一行旁边的信息入口提供用途、默认值和数值范围；主列表不增加实现说明文字。

“仅保留高德播报”一次关闭下表前五个开关，保留高德原生播报档位和独立导航音量。它不自动执行，也不覆盖升级前用户的选择。不删除地图上的信号灯、倒计时或天气显示；已经交给语音引擎播放的内容不在这里强行中断。

原包保留的音乐状态、音频通道和天气问候语等项目继续可调；本版没有恢复日志写入，也没有用日志开关控制语音。控制值通过既有 `ttsSettings.setDynamic()` 写入内存，使用 `enhanced_dynamic_settings` 保存，随后在单独的低优先级线程更新配置文件。

## 点击与过渡调整

1. 原生 GFrame 页面的公共进入、退出流程及旧资源动画路径使用 120 毫秒透明度变化，进入从 0 到 1，退出从 1 到 0，无额外起始等待。保留原有生命周期、可见性、导航逻辑及原本禁用动画的判断，旧资源 ID -1 的清理路径不变。目标包含头像、搜索及其他通过该公共路径切换的原生页面；独立 Android 权限页、系统安装器、网页内部动画、普通地图内按钮不由该过渡接口控制。
2. 巡航按钮、扩展设置入口的页面状态检查从固定等待 450 毫秒改为下一显示帧请求快照；快照在 GFrame 界面线程读取后回传，避免加快检查时从 Android 线程直接读取正在切换的页面对象。160 毫秒后再做一次结束检查。状态通知同样先在下一帧请求更新，避免固定 100 毫秒等待。这个延时原本只影响定制入口刷新，不能把它说成所有原生按钮此前都延迟 450 毫秒。
3. 地图输入队列继续合并待处理的连续 MOVE，保留 DOWN、UP、CANCEL、多指切换与原始先后顺序。将地图唤醒移出输入锁，避免引擎恢复渲染时阻塞事件派发线程取得这把锁；不使用队首插入或按下即触发点击。
4. 配置文件删除、生成改在单独工作线程执行，内存开关与偏好保存仍立即提交。导航开始时的 `/proc/self/task` 语音线程扫描也转移到低优先级工作线程，减少 Android 主线程的文件操作。

这些是代码路径和动画参数的变化，没有测得本版响应耗时、帧率或 CPU 降幅。路线计算、网络搜索、地图数据加载和原生页面构建的耗时仍然存在，不能承诺点击后数据立即完成。
